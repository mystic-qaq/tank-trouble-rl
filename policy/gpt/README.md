# GPT Sentinel

参赛入口是 **`ai.js`**，原生 JavaScript，无第三方依赖。`verify.cjs` 是验证工具，不是参赛入口。

## 接口与接入

```js
updateBot(tank, game, dt) // => { drive: -1 | 0 | 1, steer: number, shoot: boolean }
```

`steer` 限于 `[-1, 1]`，遵守游戏中 `Tank.update` 对转向输入的定义。没有瞬移、修改属性、越过冷却或额外执行游戏更新。

浏览器加载 `ai.js` 后，以下入口指向同一个函数：

```js
TT.policies.gpt
TT.updateBotGPT
TT.updateBot             // 兼容现有 js/game.js，可直接替换原控制器
```

Arena 同时装载多种策略时，请在加载本文件后保存 `TT.policies.gpt`，再由 Arena 的分发器按槽位调用。`TT.updateBot` 的赋值是为了支持当前游戏的原接口，不代表必须让所有槽位使用此策略。

CommonJS 环境：

```js
const gpt = require('./policy/gpt/ai.js');
const input = gpt(tank, game, dt);
// gpt.updateBot(...) 与 gpt.update(...) 也可用。
```

读取的观测包括自身位置、朝向、速度、冷却，存活坦克的位置和速度，场上子弹，以及地图墙体。仅使用 `map.raycast`、`map.resolveCircle` 等物理查询。所有推演在私有副本中完成；状态通过 WeakMap 按坦克、地图隔离。不会读取其他控制器、其他策略的内存或 `tank.ai`。

## 根据实际引擎确认的规则

- 每发命中即淘汰，自己发出的子弹同样可以击杀自己。
- 每回合最后存活的一辆车获得一胜；同时全灭则无人得胜。达到设定胜场数才赢下整场。
- 击杀对手记 +1，自杀记 −1；击杀统计不直接决定回合胜负。
- 每辆车至多有 5 发存活子弹，开火间隔 0.42 秒。子弹速度 620 px/s，寿命 6 秒。
- 引擎允许前 5 次反弹，第 6 次撞墙时销毁。子弹出生后的 0.07 秒不判定对发射者的伤害。
- 坦克半径 16 px，子弹半径 3.2 px；最大前进速度 178 px/s，倒车为其 66%，转向上限 3.3 rad/s。
- 转向、加速、位移、碰墙、开火依次执行。开火还会使车速减少 16 px/s。预测与触发判断遵守这一顺序。
- 两张 16 × 10 的地图按回合交替，出生位置随机。墙体会挡车并反射子弹。

规则来自 `util.js`、`map.js`、`entities.js`、`game.js` 及界面文件。未读取 `js/ai.js` 或其他 AI 的 policy。

## 策略

1. **存活优先。** 在未来约 0.8 秒内模拟现有子弹的完整反弹路径，使用同步运动线段距离识别高速交叉命中。另以较低权重估计敌方当前炮管及即将完成瞄准的威胁。
2. **短期路线搜索。** 有界束搜索比较前进、倒车、刹车、转向、寻路和保持瞄准等操作，保留多种走位。推演包括真实加速、制动、墙角碰撞与碰墙减速。碰弹代价远高于射击收益。
3. **移动预瞄。** 根据观测到的车速和转向，维护转弯及直行两种未来轨迹，按弹丸飞行时间迭代求解提前量。瞄准奖励覆盖整段过程，避免反复推迟开火。
4. **反弹射击。** 镜像目标生成单次反弹瞄准候选，验证入射、反射两段是否畅通，再追踪实际多次反弹弹道评分。开火前还会检查本帧实际炮口及短期自身路线，拒绝明显会反弹自伤的射击。
5. **迷宫通行。** 缓存带车体宽度验证的网格连通图与最短路，并在安全直通时平滑路径。避免只有炮弹能通过、车体却过不去的墙角。
6. **混战节奏。** 五车以上时短暂利用出生掩体，保留机会射击与主动躲避；存活者减少后主动接敌。等待有时间上限。走位还考虑墙边剩余空间，减少把自己逼进角落。

平时约 20 Hz 重新规划，新子弹出现时提前规划；开火和输入范围检查仍随游戏每帧执行。策略不使用随机数，不依赖玩家编号或固定出生点；编号只用于初始左右偏好的对称破局。

## 验证

在项目根目录运行：

```powershell
node policy/gpt/verify.cjs --quick
node policy/gpt/verify.cjs
node policy/gpt/verify.cjs --selfplay
```

验证程序只加载游戏的数学、地图、实体、回合引擎，以及本目录的策略。它检查只读性、控制范围、30/60 Hz 行为、静止与移动目标、隔墙反弹击杀、来弹躲避、两张地图的寻路，并可执行对局。

加速后的几何查询还会与原引擎逐项比较：5,000 次射线查询和 5,000 次车体碰撞。最终版本的 10 个寻路出生样本全部通过；12 局简单测试炮手对战取得 9 胜（8 局双车对局全胜，4 局八车混战 1 胜），该参赛槽位没有自杀。两局八车同策略对战均正常结束，但全场仍出现了反弹自伤，说明短期预测不能保证永不自伤。

`validation.json` 与 `validation-selfplay.json` 保存验证摘要及参赛文件 SHA-256。自我对战报告的胜负数只对应轮换观察的那个槽位，不是不同策略之间的胜率；其中自杀数统计所有槽位。

普通对局使用验证文件内自行编写的简单测试炮手，其行为仅用于回归验证：沿公开寻路结果追踪，瞄准当前敌人位置并开火。它不是其他参赛 AI，也不代表 Arena 的实际难度。

额外选项通过环境变量传入：`GPT_ROUNDS` 控制对局数，`GPT_PLAYERS` 控制人数，`GPT_NAV_CASES` 控制寻路出生样本数。`GPT_ONLY_ROUND` 可复现某一局；`GPT_TRACE=1` 会将该槽位的观测与动作写入本目录，便于诊断。

这是基于公开局面进行预测的策略；对方未来的实际转向和新开火仍存在不确定性。验证结果只能说明这些测试条件下的表现，Arena 战绩应以正式对战为准。
