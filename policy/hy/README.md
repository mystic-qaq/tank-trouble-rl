# HY · Tank Trouble Arena 策略

单文件、零依赖、浏览器与 Node 都能直接加载。目标很明确：**活到最后一辆车**。

---

## 一、文件与接入

| 文件 | 用途 |
| --- | --- |
| `policy.js` | 主实现（UMD：浏览器 `<script>` / CommonJS 均可） |
| `policy.mjs`、`index.mjs`、`hy.mjs` | ESM 入口（default + 命名导出） |
| `index.js`、`hy_policy.js` | CommonJS 别名入口 |
| `package.json` | `main` / `module` / `exports` 映射 |
| `build.mjs` | 从 `policy.js` 重新生成上述入口（`node policy/hy/build.mjs`） |
| `test/sim.js` | 调用真实引擎的无头对战统计 |
| `test/interface.js` | 接入形态自检 |

所有入口共享同一个 API 实例，重复加载不会重复初始化。

### 接入方式（任选其一，全部已自检）

- **浏览器 script**：`<script src="policy/hy/policy.js"></script>` → `HYPolicy(...)`、`TT.Policies.hy(...)`、`window.policy(...)`。
- **引擎 bot 钩子**：脚本会自动包装 `TT.updateBot`。给需要接管的坦克打 `__hy = true` 或 `policy = 'hy'`（也认 `game.policies[i] === 'hy'` / `game.slots[i] === 'hy'` 等），未标记的车仍由原 bot 控制，绝不误接管。也可手动 `HYPolicy.install()`，或 `HYPolicy.configure({ takeoverAll: true })` 全量接管。
- **CommonJS**：`const hy = require('policy/hy')`（或 `require('policy/hy/policy.js')`）。
- **ESM**：`import hy from './policy/hy/policy.mjs'`（`default` / `decide` / `act` / `policy` / `updateBot` 均可）。
- **对象形态**：函数对象上同时带 `decide` / `act` / `step` / `updateBot` / `configure` / `reset` / 生命周期空方法 / `meta`。

### 调用签名

```
hy(tank, game, dt)      引擎原生
hy(game, tank, dt)      参数颠倒也可
hy(state)               快照 { self|me|you|tank|player, tanks, bullets, walls, time|tick, dt }
hy(state, dt)
```

缺 `walls` 时会用与游戏一致的确定性算法重建两张固定种子地图，并用"实体不该在墙里 / 子弹不该穿墙"逐帧投票选出当前地图；都不吻合则退化为只信外墙。

### 返回值

`{ drive, steer, shoot }`：`drive ∈ [-1,1]`、`steer ∈ [-1,1]`（**浮点**，便于精确瞄准）、`shoot` 布尔。
为兼容不同 Arena，同时附带 `throttle` / `move` / `turn` / `rotate` / `fire` / `shooting` 和布尔 `up` / `down` / `left` / `right` / `forward` / `backward` / `reverse`。

## 二、对规则的理解（决定策略取舍）

- 一回合胜负只看**谁活到最后**；击杀只进榜单，自杀 −1 且直接丢掉本回合。先到 N 胜夺冠。
- 子弹 620 px/s、r=3.2、最多反弹 5 次、寿命 6 s、出生 0.07 s 自伤豁免、每车最多 5 发在场。
- 坦克 r=16、178 px/s（倒车 0.66×）、加速度 920 / 刹车 1150、转向 3.3 rad/s、开火冷却 0.42 s。
- 墙是 10 px 厚 AABB，贴在 80 px 网格线上；两张固定种子地图按回合交替；出生点两两不可直瞄。
- 引擎 `Tank.update()` **先按 steer 转向，再用新角度开火** → 可用 `steer = Δ / (3.3·dt)` 在同一帧精确对准并击发，避开"每帧转过头"的振荡陷阱。

结论：**防守远重于进攻**。8 车混战里 7 个对手会互相消耗；绝大多数失败来自自伤和 100~200 px 的近距离直射弹（飞行仅 0.2~0.3 s，转向来不及躲）。

## 三、策略组成

1. **解析弹道预测**：完整复刻 `raycast` / 法线反射 / 0.8 px 推离 / 0.7 px 步长扣除 / 第 6 次撞墙消亡，对每颗在场子弹生成 0.9 s 内逐帧位置（含所有反弹段）。
2. **威胁矩阵 + 模型预测控制**：把 18 组 `(steer, drive)` 候选按真实加速度、转速、撞墙推挤滚动模拟 0.9 s，逐帧累加"与子弹的距离惩罚"，再叠加离敌距离、开阔度、贴墙、抖动、位移等项，取总代价最小的机动。命中风险权重远高于开火收益。
3. **同帧精确瞄准 + 自伤否决**：任何候选射击都先模拟整条弹道，若命中敌人前（含预判落空的缓冲）会绕回自己身边就直接否决；同时在场自弹限制为 2~4 发。
4. **反弹猎杀**：无直瞄时每 ~0.2 s 扫描 72 个角度，用真实反弹弹道找能打中敌人外推位置的球，并剔除自伤角。
5. **BFS 寻路**：从墙 AABB 反推 16×10 网格的通行边，每隔 0.3 s 求一次到最近敌人的路径，取"最远可见路点"喂给 MPC。只有局部评分的走位会永远绕不过墙，1v1 残局会拖成超时。
6. **虚拟威胁**：对每个看得见自己的敌人，布一条"敌人→我"和一条"敌人→我 0.3 s 后位置"（对手会打提前量）的假弹道，在子弹出现前就侧向离开射线。
7. **残局压制射击**：对手普遍不躲子弹、而 MPC 会躲自己的子弹。残局无直瞄时，从 9 个候选方向里挑"前期弹道不回自己身边、且会穿过敌方区域"的角度打一发反弹弹，把僵持磨掉——不是盲射，仍逐条弹道筛选。
8. **苟住优先 + 僵局破局**：低侵略度时不主动送脸；回合进行 6 s 后侵略度线性上升，残局/少车时额外加成，放宽自伤阈值、允许更多在场子弹、主动压上。
9. **卡住自救**：用**位移**（不是速度）判定顶墙空转，触发倒车 + 反向转向。
10. **零崩溃**：`decide` 全程 try/catch，任何异常退化为安全静止动作；所有输入字段做缺省归一化。

## 四、自测

```
node policy/hy/test/interface.js
node policy/hy/test/sim.js --matches 20 --rounds 3 --frames 12000 --diag
node policy/hy/test/sim.js --baseline --matches 10
```

`sim.js` 直接加载真实 `js/*.js`（stub 掉 DOM/Audio），让 1 辆 HY 对战 7 辆内置 bot，先到 3 胜，固定随机种子便于对比。

### 实测成绩

配置：1 辆 HY 对战 7 辆游戏内置 bot，先到 3 胜，20 场比赛 / 100 回合，固定随机种子；基线为 8 辆全内置 bot、10 场 / 84 回合。

| 指标 | 内置 bot 基线 | HY 策略 |
| --- | --- | --- |
| **夺冠率** | 10.0%（1/10） | **85.0%（17/20）** |
| 回合胜率 | 14.3%（12/84） | **54.0%（54/100）** |
| 自杀 | 18 次 / 84 回合 | **2 次 / 100 回合** |
| 僵局超时（12000 帧） | 1/10 场 | **1/20 场** |
| 策略抛错 | — | **0** |

调参过程中最关键的三步：把"自伤否决 + 反弹弹道预测"做全（冠军率 70% → 90%/10 局）、加入 BFS 寻路解决 1v1 绕不过墙（20 局冠军率 65% → 80%、僵局 7 → 4）、加入残局压制射击（80% → **85%**、僵局 4 → **1**）。

注意：以上是对内置 bot 的成绩；Arena 里对手是别的 AI 策略，绝对数值会变，但"不自杀、会躲反弹弹、能收掉残局"这三点对所有对手都成立。

## 五、约束与边界

- 全部产出只在 `policy/hy/` 内；**没有读取任何其他 AI 的 policy 文件**，没有修改游戏源码。
- 不依赖网络、不依赖外部库、不读取本地文件；策略本身只用传入的状态。
- 未标记的坦克一律交回原 bot，多个策略共存时互不干扰。
