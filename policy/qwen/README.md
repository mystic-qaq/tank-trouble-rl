# Tank Trouble · Qwen 策略

一句话：**这是一场「谁最后活着谁赢」的游戏，所以我把全部设计押在「绝不打死自己 + 只在必杀时开火 + 掩体走位」上，而不是一味抢击杀。**

---

## 1. 接入方式（给 Arena 装载器）

策略本体只有一个文件：`policy/qwen/policy.js`，一个**普通经典脚本**（非 ES Module），
浏览器 `<script>` 直接能跑，Node 也能 `require`。

它遵循和游戏内置 bot 完全相同的契约：

```js
TT.policies.qwen.update(tank, game, dt)
// -> { drive: -1..1, steer: -1..1, shoot: boolean }
```

三种接法，任选其一：

**A. Arena 自己做路由（推荐）**

```js
const qwen = TT.policies.qwen.update;          // 或 window.QWEN_TANK.update
TT.updateBot = (tank, game, dt) =>
  tank.index === MY_SEAT ? qwen(tank, game, dt) : builtin(tank, game, dt);
```

**B. 加载现成适配器**（会改写 `TT.updateBot`，只适合没有自建路由的场合）

```html
<script src="js/ai.js"></script>
<script src="policy/qwen/policy.js"></script>
<script src="policy/qwen/qwen-adapter.js"></script>  <!-- ?qwen=0 或 ?qwen=all -->
```

**C. 工厂式**（每辆车一个独立实例）

```js
const brain = TT.policies.qwen.create(tank, game); // { update(tank, game, dt) }
```

别名：`update / think / step / decide / onTick / play / act / control` 都是同一个函数；
全局名 `TT.policies.qwen`、`TT.qwenPolicy`、`window.QWEN_TANK`、`window.TT_QWEN` 均可用。
脚本**不会**自动改写 `TT.updateBot`，不会污染别的 AI。

依赖：只用 `TT.CFG`（读不到就用内置兜底值）、`game.map` / `game.tanks` / `game.bullets` /
`game.kills` 这些公开字段。没有 DOM、没有网络、没有外部库。

## 2. 我从规则里读到的取胜要点

| 规则事实 | 策略结论 |
| --- | --- |
| 回合唯一的胜利条件是 `alive <= 1`，赢家 = 最后一个活着的 | **生存率 == 回合胜率**。活着比杀人值钱 |
| 一枪毙命；自杀 −1、杀他人 +1，但击杀不计入胜负 | 击杀只是「减少场上人数」的手段 |
| 子弹速度 620、坦克最快 178、反弹 5 次、寿命 6 秒 | 近距命中容易；远距要提前量；流弹是主要死因 |
| 内置 bot 群体里约 23% 的死因是自己子弹反弹 | **零自杀**就是白捡的巨大优势 |
| 履带操控：炮管 = 车体朝向，不能侧移；转向 3.3 rad/s | 用「开枪 → 侧移 → 回身」的节奏，而不是站桩对狙 |
| 出生点两两互不可见（`hasClearShot == false`） | 开局一定是摸索遭遇，掩体价值极高 |
| 只有 2 张固定地图，按回合交替 | 可以离线预计算地图结构（格间可见性 / 全对最短路） |

## 3. 策略结构

```
感知   每个敌人 0.1~0.2s 窗口的速度回归 → 线性预测位置
       谁「快被别人的子弹打死」→ 不补枪、不凑热闹
       子弹走廊全局热力图（同帧多车共享，省算力）

弹道   与游戏 Bullet.update 同一套反射物理（0.8px 法向偏移 / 每弹 -0.7px 能量 /
       >5 次反弹消失 / 炮口顶墙哑火），连续解析扫掠而非逐步模拟
       命中判定用「直线段 vs 匀速移动圆」的解析最近点，一次算清

开火   只打「模拟确定命中」的枪；并且全程检查弹道与我自己未来 3 条轨迹的
       时间相关最近距离 —— 余量不足直接放弃这一枪（绝不反弹自杀）
       允许精度随距离自适应：100px 处约 ±11°，400px 处只允许 ±2.7°
       僵局时补「压制弹」，逼死角里的对手动身

反弹弹 墙面镜像求入射点，两段都要通才考虑 —— 打得掩体后面的敌人

走位   候选格打分：被几个敌人直视(硬约束) / 子弹走廊热力 / 向猎杀目标推进 /
       贴墙掩体 / 有无退路 / 与敌人挤在一起 / 路线记忆（走不通的格子拉黑 7 秒）

躲避   枚举 9 种机动 → 各自 0.95s 运动学推演 → 选「来袭弹到我最远距离」最大的
       并且把「对手枪口已经指着我、随时能开火」当作预判威胁，不等子弹出膛
       基线（原地不动）不参与选择：绝不站桩当靶子

阶段   prowl 潜伏（多人时贴掩体、避锋芒）→ hunt 清扫 → duel 单挑
       僵局升级：一段时间没人死 / 回合过长 → 逐步放开自伤余量、强制推进，
       保证不会出现「两个 AI 各自躲到永远」的死局
```

## 4. 自测工具（都在本目录，不动游戏本体）

```bash
cd policy/qwen/sim
node smoke.mjs                  # 无头 Arena 冒烟：跑的是游戏真实 js
node bench.mjs --n 12           # qwen 1 席 vs 7 个内置 bot
node inspect.mjs 7 0            # 单场诊断：状态占比 / 开枪数 / 死因 / 耗时
node deaths.mjs 12 0            # 死因剖析（几点几分死在谁手里、当时几人在场）
node stall.mjs 10               # 回合时长分布，检查僵局
node navtest.mjs                # 导航表自检：next[] 是否真的走得通（50880 对格子）
node robust.mjs 10              # 鲁棒性体检：单图 / 人数 / 帧率 / 镜像自战
node gauntlet.mjs 14            # 拉练：对上 sim/hardbot.mjs 的「认真版」对手
node runner.mjs --n 40 --cfg '{"selfMargin":10}'   # 单配置，输出一行 JSON
node sweep.mjs cfg-t6.json --n 40 --jobs 14        # 并行 A/B 调参，带显著性
```

无头 Arena 的做法：`vm` 沙箱里加载 `js/{util,map,entities,ai,game}.js`，
把 DOM / Canvas / WebAudio 全部打桩，固定 `dt` 手动驱动 `game.update()`，
按座位把 `TT.updateBot` 分发给不同策略。所以测出来的就是真实规则，
仿真速度约 50~120× 实时。

浏览器里直接双击打开 `policy/qwen/arena.html` 可以观战：能切换 Qwen 座位数
（1 → 8 全接管）、目标胜场，右下角实时显示策略决策与耗时。

## 5. 实测成绩（无头 Arena，跑的是游戏真实 js）

### 5.1 主场景：1 席 Qwen vs 7 个内置 bot，先到 4 胜，80 场

| 指标 | Qwen | 内置 bot | 说明 |
| --- | --- | --- | --- |
| 回合胜率（= 生存率） | **40.0%** | 8.7% | 8 车公平线是 12.5%，即 **3.2×** |
| 场胜率 | **86.3%** | — | 一场比赛的获胜率 |
| 1v1 收尾转化 | **79.7%** | — | 打进最后单挑时赢下的比例 |
| 自杀 / 回合 | **0.020** | 0.32 | 低一个数量级 —— 这是胜率的主要来源 |
| 击杀 / 回合 | 0.60 | 0.28 | |
| 僵局（回合打不完） | 1/80 场 | — | 已专门做了反僵局分级 |

参数扫描（14 配置 × 40 场，`node sweep.mjs cfg-t6.json --n 40 --jobs 14`）的关键结论：
去掉「开枪—侧移—回身」会让场胜率从 87.5% 掉到 77.5%；`maxLive=2`（太保守）掉 4.8%；
`visFree=0`（一点都不能被看见）反而掉 1.8% —— 过度怂和过度莽都亏，当前取值在两者之间。
熔断（超长回合强制收尾）对胜率无损失（40.0% vs 40.2%），但能把僵局从 2/80 压到 1/80，所以保留。

### 5.2 鲁棒性体检（`node robust.mjs`）

| 场景 | 回合胜率 | 相对公平线 | 场胜率 |
| --- | --- | --- | --- |
| 常规 1v7（双图轮换） | 38.2% | 3.06× | 90% |
| 只用地图 A | 37.1% | 2.97× | 90% |
| 只用地图 B | 38.9% | 3.12× | 80% |
| 4 车局 1v3 | 62.5% | 2.50× | 100% |
| 6 车局 1v5 | 44.2% | 2.65× | 70% |
| 2 席 Qwen + 6 内置 | 67.1%（两席合计） | 2.68× | 100% |
| 帧率 dt=1/30 | 35.9% | 2.87× | 90% |
| 帧率 dt=1/15 | 46.0% | 3.68× | 100% |
| 帧率 dt=1/120 | 40.4% | 3.24× | 90% |

不同地图、不同人数、不同帧率都不塌，说明决策是**按时间**而不是按帧数驱动的。

### 5.3 对强手拉练（`node gauntlet.mjs`）

内置 bot 太弱，不足以说明问题，所以另写了一个「认真版」对手 `sim/hardbot.mjs`
（完美提前量、主动追到 180px、会侧移躲弹、用满 5 发子弹）。

| 场景 | 回合胜率 | 相对公平线 | 自杀 |
| --- | --- | --- | --- |
| 1 Qwen vs 7 强敌 | **97.1%** | 7.77× | 1 次 / 14 场 |
| 1 Qwen vs 3 强敌（4 车） | 95.9% | 3.84× | 4 次 |
| 1 Qwen vs 7 半吊子（不躲弹） | 97.4% | 7.79× | 7 次 |

注意：这里剩下的「僵局」绝大多数是 **Qwen 已经阵亡后，几个强敌互相磨**（诊断脚本
打印出的幸存者是 `[2,3,4,5,6,7]` 而不含 0 号位），不是本策略造成的；真实 Arena 里
各家策略都会主动找人对枪，这个形态不太会出现。

### 5.4 性能与浏览器验证

- 浏览器实跑（`policy/qwen/arena.html`）：真实引擎驱动本策略，**0 次异常**；
  单次调用均值 **0.59 ms**，1 席位时约占 60fps 预算的 3.5%；即便 8 席全用本策略也约 1.5 ms/帧。
- 地图模型改成惰性可见性后，首次调用峰值从 131ms 降到 ~31ms（主要是 JIT 预热），不再卡顿。
- 导航表自检 `node navtest.mjs`：两张地图共 50880 对格子，坏路径 **0** 条。
- 尚未做的验证：截图级的人工观感确认（内置浏览器标签处于隐藏状态，rAF 暂停，
  只能通过脚本驱动帧来验证）；真实对手是其他家 AI，强度未知，上面的数字不能直接外推。

## 6. 如果 Arena 只给一个座位，需要改哪里

只需要把 `TT.updateBot` 分发到 `TT.policies.qwen.update`，其余都不用动。
本策略不依赖座位号、不读写 `localStorage`、不改写游戏全局（除了注册自己的
`TT.policies.qwen`），也不会去碰别的策略目录。
