# RL V2：先通过能力验收，再训练两个最终目标

日期：2026-11-06。状态：重新设计完成，尚未实现或启动 V2 训练。
用户已明确停止 V1。本文件不构成恢复 V1 或自动启动训练的指令。

## 1. 核心决定

保留真实 JS 引擎、60 秒比赛规则与两个最终目标；重新设计输入表示、动作建模、示范数据、初始化门槛、长程回报与采样架构。

主路线：

    引擎/动作契约 → 几何特征与技能数据 → BC + DAgger → 实战准入
        → 两个独立模型的完整回合 PPO → 固定开发验证 → 独立最终测试

继续采用 PPO 作为第一条可控基线，不同时更换为复杂离策略算法和多机系统。
先用完整回合与 Monte Carlo 回报消除本任务的短 trace 问题，后续用消融决定是否需要更复杂方法。

两模型共享数据规范和初始几何编码知识；最终权重、优化器、价值函数、教师约束与模型选择各自独立。
HY/GPT 给各自的行为头供标签，不将两种相冲突的动作简单平均。策略必须自己决定行动，不作为现有固定策略的选择器。

## 2. 必须解决的 V1 故障

| V1 证据 | V2 的对应措施 |
| --- | --- |
| 真正的训练开火标签仅 354 / 597 条 | 数据按独立布局与实际射击事件计数，不按总帧数宣布完成 |
| BC 开火召回为 0，仍进入 PPO | 射击/自伤/实际对局作为硬准入门槛 |
| 加权分类校准后，所有 BC 开火概率低于 0.5 | 训练、选择、导出使用同一动作语义；导出时不另改偏置/阈值 |
| 分别预测转向与开火，缺乏动作间条件关系 | 开火头条件于已选择的移动、转向及预计炮口状态 |
| 净击杀靠不射击趋近 0 | 微任务提供真正成功攻击；对击杀和自毁分别监控；不奖励开枪次数 |
| 每段仅 4.27 秒，终局信号依赖早期弱 critic | 首先采集完整 agent episode，γ=1、λ=1 的 MC 回报与完整终止边界 |
| 小网络从原始墙位图自己学反弹与遮挡 | 输入公共几何/威胁特征和实体关系，不要求网络从零发现物理 |
| 同步小批量 CPU/Node 通信限制吞吐 | 独立环境异步采样、统一批量推理、二进制传输，严格管理 PPO 版本 |

不能把“训练奖励不再负数”“总 BC loss 下降”“显存增加”作为能力通过的证据。

## 3. 目标、规则与评价分布先冻结

比赛 60 秒，超时平局；物理 60 Hz，保留原来的动作能力和连续小数转向，不先引入动作降频这一新变量。

- rl_win：整局赢得 +1，其他结果 0。
- rl_frag：逐事件击杀他人 +1、自毁 −1；被别人击杀不另扣分。
- 训练死亡后的终止采用已验证规则：胜率收益已确定为 0 可结束；净击杀必须等所有己方在场弹结算完，或整个回合先结束。
- 正式评估始终完整跑回合，保留平局、击杀与自毁。

最终场景分布 D：N=2…8 各占 1/7，两张现有地图各半，出生点/朝向/席位配平，背景名单分层覆盖。
对新地图的泛化另设测试，不将“换出生点”称为新地图泛化。

主比较采用同背景、同布局、同席位，只替换被测主体的成对对局。
背景池与是否允许同 policy 多副本预先写入测试清单；实际八策略无重复的部署阵容还须单独回归。
开发、最终测试的布局种子和部分背景名单组合独立划分。最终测试不参与阈值、超参或模型选择。

胜率型可以学出合理保守打法。如果它的真实胜率持续提高，不因“击杀不多”否决它；
净击杀型必须真正获得更高净击杀，不能把零攻击、零自毁称为目标已实现。

## 4. 状态表示与动作接口

### 4.1 状态：让网络学习战术，不重学几何运算

保留所有公开实体状态，并加入以下特征：

- 自身坐标/速度/角度/冷却/弹量/剩余时间，最近约 0.25–0.5 秒的动作或短历史编码。
- 小型地图 CNN 与自身局部墙体信息，约 16–24 个方向的障碍距离。
- 对每个对手：相对位置/速度/方位、视线、预计截击角、墙体遮挡、格点路径距离与下一通路方向。
- 对全部最多 40 发子弹：当前状态、归属、已反弹次数，以及未来若干时点的预计接近/碰撞威胁；不只看最近几发。
- 在选定本帧移动和转向后，补充预计自身姿态、炮口是否被墙挡住和相关射击几何。

子弹反弹预测利用公开地图和现有引擎规则；对手未来位置仅是恒速等明确假设下的预测，不输入真实未来动作。
网络不读取策略名称、私有记忆、未来随机数或教师隐藏目标。

采用自车 query 对敌车/子弹 token 做交叉注意力，保留目标与威胁关系；避免早期只靠 mean/max 把所有实体挤成一个摘要。
第一候选 actor 约 0.5–2M 参数，critic 可略大。容量只是工程起点，必须通过消融验证，不为了填显存盲目增大。

静态地图路径信息按地图缓存。几何特征成本单独测量，不让新增特征抵消所有采样收益。
第一版不重写 Python/GPU 物理；实际命中仍由原 JS 引擎判定。

### 4.2 动作：保留精确转向，明确射击机会

drive 保留后退/停止/前进。转向使用“左/零/右 + 连续幅度”的条件分布候选，避免对冲突左右标签求均值后学成不转；
连续幅度保留细微瞄准能力。该分布先完成 log-prob、熵、边界和导出一致性测试，再用于训练。
如果相同预算下该方案未优于原连续分布，保留原分布并使用更小、经实战验证的初始探索噪声。

射击头输入已选运动动作及预计姿态。PPO 更新时用记录下来的运动动作重算条件概率，不能重新采运动再算开火 log-prob。
这些条件计算在同一次批量 actor 前向中完成，不为了射击头逐帧增加一次 Node/Python 往返。
硬 mask 优先使用环境提供的冷却/弹量/存活就绪标志；预计炮口和风险是特征，实际物理与哑火仍由引擎判定。

机械合法性与“战术是否值得开火”分开：

- 已死亡或本帧绝对不能产生射击的冷却/弹量状态，不让无效开火样本主导分类和 actor loss。
- 合法性按原引擎的先更新冷却、转向、移动、再射击顺序验证；不能用错误的提前状态屏蔽本帧即将就绪的射击。
- 不用“预计有风险”永久硬屏蔽射击；合理的冒险/换杀仍由策略决定。
- 对加权采样和分类输出的含义明确记录。导出不再额外扣一次类别先验。
- 预先选定部署解码方式，并按它做主评估；探索模式只作为训练诊断，不能拿两种动作规则的成绩混在一起。

## 5. 事件数据与课程

### 5.1 建立真实射击事件账本

每发弹有 shot_id，关联：动作请求、真实产生子弹、因墙哑火/冷却/弹量无效、反弹、击杀他人、自毁、消失、回合结果。
“请求 shoot=true”不等于真的射出，更不等于有效攻击。

每份教师新数据的初始覆盖目标：

- 至少 1,000 个独立出生布局，两个地图与不同人数覆盖；
- 至少 20,000 次真实射出事件，覆盖直接射击/反弹/移动/拥挤/临界冷却等情况；
- 相当数量的困难负样本：角度相近但被挡、即将自伤、弹量满、等待更有利时机等；
- 原有 354/597 个训练开火样本可保留，但不能作为全部攻击基础。

事件目标是初始工程预算，不保证达到这些数量就一定学会。若独立布局或射击覆盖不达标，不用复制连续帧凑数量。
训练可以过采样关键事件；验证保持自然出现频率，报告条件召回/精度与实际效果。
数据按完整轨迹、布局和场景分组切分，邻近帧不能跨训练/验证泄漏。

### 5.2 在完整混战之前验证技能

从这些可控场景开始：

1. 无墙固定目标，学习精确转向与有效发射。
2. 移动目标与射击时机。
3. 一次反弹、炮口贴墙、自己子弹回流。
4. 单发/多发来弹、狭窄通道，验证避弹。
5. 简单地图 1v1，再扩展到 3–4 人与 5–8 人。

微任务可使用命中/避弹等技能目标。它们是初始化任务，不把这些分数混成最终比赛奖励。
最终目标阶段重新拟合对应 critic，不能沿用不匹配的微任务价值标签。
强教师和目标分布场景始终有留出验证，避免只会打简单靶。

### 5.3 BC + DAgger，而非固定训练若干 epoch 后自动晋级

第一轮 BC 后让学生自己运行，由 HY/GPT 在学生访问的状态上提供各自标签。
教师作为逐局重置的 shadow controller 观察同一历史，不执行其动作；随机流与对手隔离。
针对学生失败场景补数据，不只重复教师的成功轨迹。
监督标注保留完整的教师联合动作，开火标签条件于对应的教师运动动作；
不能把教师基于自身瞄准动作作出的 shoot 标签，错误配到学生另一套运动动作上。
若需要给学生运动方案标射击结果，另用真实引擎微任务/实际交互生成对应标签，不伪造反事实结果。

关键动作损失独立报告；移动/转向/射击采用独立头和可审计权重。
不让“多数时候不射击”的高准确率掩盖不会攻击。

## 6. 必须通过的准入门槛

下面的数值是建议在实验前冻结的验收标准，不是已验证的普遍常数。

| 门槛 | 通过条件 | 失败后的动作 |
| --- | --- | --- |
| G0 引擎与分布 | 60 秒、边界帧、mask/log-prob、事件归因、导出均一致；所有结果可重放 | 修实现，不训练长跑 |
| G1 基础射击 | 留出微任务命中率达到同条件参考约 90%，贴墙/回流自毁不超过预设上限 | 改输入/事件标签/控制头 |
| G2 BC 关键动作 | 自然合法机会上的召回、精度、瞄准误差可用；不再出现确定性零开火 | 补数据/DAgger/校验解码 |
| G3 BC 实战 | 各自主要目标达到教师约 80%，且有真实有效攻击；用成对置信区间确认 | 不进入最终 PPO |
| G4 短 RL | 相同场景下较 BC 有可复现收益，没有回退成零攻击 | 排查/回滚/消融，不扩预算 |
| G5 正式替换 | 超过 HY/GPT 且达到预先冻结的最终差值与置信区间门槛 | 不替换正式策略 |

G2 可先将射击召回 80%、精度 70%作为工程筛查起点，但教师动作并非唯一正确动作，最终以真实命中、自伤和 G3 为主。
若模型做出不同于教师但实际更好的攻击，不机械否决。

G3 开发集每个人数至少约 100 局、并取 2N 的倍数形成完整布局/地图轮转；约 700–800 个成对场景起步。
若比较 S 与 T，可用 paired bootstrap 对 S−0.8T 的主指标检验；net 基线不为正时改用绝对正收益门槛。
名单共享布局时按整个共享随机块重采样，不能把每帧或相关对局当作独立样本。

## 7. 最终 RL：先试完整回合 PPO

第一版最终 RL 使用：

- 每次冻结当前 actor 版本，采集约 64–128 个完整 agent episode；每个物理步仍 1/60 秒。
- γ=1，初始 λ=1，使用实际终止边界的完整 Monte Carlo reward-to-go 减当前 V(s) 作为 advantage。
- 初期用当前学生自己的完整回合回报拟合 critic，可先短暂冻结 actor；不能把教师回报误当作学生的 on-policy 价值。
- PPO 阶段 actor/critic 主干分别维护，或明确隔离 critic 对预训练 actor 的梯度，避免随机价值头破坏已经验收的行为。
- critic 预热用单独的前置样本；正式 actor 更新保留采样时的 old value/log-prob，不一边拟合当前回报一边重写它们。
- 保留适当的 BC/KL 辅助约束，在固定评估证明能力稳定后逐步放松，不按固定帧数机械归零。
- 新鲜 on-policy 样本用于 PPO；旧示范/成功案例只用于明确标记的辅助监督。它们不能直接混作新策略 rollout。
- 分动作头管理探索；连续转向初始探索围绕已经验证的控制能力，避免 V1 一开始就强烈扰动瞄准。

这会增加每次更新前的采集量，但 60 秒是有限上界，且回报范围清晰：win 为 0/1，frag 在本游戏人数与单次死亡约束下有界。
好处是终局奖励能进入整条轨迹的回报，不再被短 rollout/弱 bootstrap 组合隔开。

若完整回合估计方差过大，再做一个受控消融：较长 rollout + 以秒定义的 GAE trace。
例如取 τ=10 秒时每个 1/60 秒动作 λ=exp(−1/(60τ))≈0.99833；这仅是比较起点。
不能在没有比较的情况下称它一定优于 λ=1。

可保留旧的 λ=.98 配置作一个小预算对照，不再让它成为默认长跑方案。
微任务塑形和最终比赛指标分别记账；默认不增加“每开一枪”或“每活一秒”奖励。

## 8. 利用 Server3090 的方式

已确认服务器为双路 EPYC 7H12：128 个物理核/256 线程、约 247 GiB 内存、8×24 GiB 3090。
资源是共享的；实施时重新检查占用，不能将全部逻辑核视作独占物理核。

V1 每批 16 环境的短测：模拟与通信 28.6 ms、推理与动作回传 2.8 ms。
因此先改数据供给和有效经验数量，不把 DDP 或显存占满作为目标。

### 8.1 阶段资源配置

| 阶段 | CPU/环境配置 | GPU 配置 | 目的 |
| --- | --- | --- | --- |
| 接口/微任务验证 | 少量进程，固定小场景 | 0–1 张 | 低成本排错 |
| 数据采集 + BC/DAgger | 先 32 个 worker 进程，候选 64；每个 2–4 个独立环境 | 最多 4 张，做少量独立候选 | 增加事件覆盖、筛选输入/动作方案 |
| 两目标短 RL | 两模型共用总 CPU 上限，不各自无限扩容 | 每模型 1 张，另 1 张可做独立评估 | 验证能否超过合格 BC |
| 正式训练/复现 | 经吞吐实测后分批运行 | 额外卡优先用于独立 seed/消融 | 验证可靠性，避免只得到一个幸运模型 |

第一阶段同时最多使用约 64 个 CPU worker；具体数目按 NUMA、其他负载和实测吞吐收敛。
不启动 8 个 CPU 饥饿的训练器争抢同一批模拟。

### 8.2 采样与推理

环境独立推进，请求集中成批推理：目标批量 32–128，最久等待约 1–2 ms，再由实测调整。
不同环境可以异步完成，消除所有环境每一步等待最慢环境的屏障。
不逐帧使用 base64 JSON 搬运完整观测；优先使用共享内存/二进制环形缓冲和固定 schema。
轻量控制消息与大体积状态分离，限制 PyTorch/BLAS 后台线程，避免线程过量。

PPO 的策略版本必须严格管理：采集同一版本完整回合，达到批次后停止开启新回合、收齐当前轨迹，再更新并切换版本。
不会把“异步采样”偷换成可以无限混入陈旧策略经验。若以后真正解耦 actor/learner 并引入策略滞后，需采用相应校正算法并独立验证。
完整回合数量是批次目标，收齐尾部可能使实际数量增加；每模型默认 32–64 个活跃环境，按这个数量预先计算批次上限。
额外环境用于数据采集、评估或后续经过预算确认的扩展，不在同一版本里无上限启动新回合。

先比较 8/16/32/64 workers，报告：完整有效回合/秒、真实射击事件/秒、独立布局数、PPO 决策样本/秒、模拟/通信/推理/优化各阶段耗时。
增加进程不增吞吐或明显损害其他任务时回退。GPU 利用率只是辅助系统指标。

## 9. 分批预算与停止条件

不一次承诺数千万帧。以下是初始上限，达到上限未通过门槛就停并报告原因；时间上限不是预计完成时间。

1. **契约与吞吐验证**：不做长训练；先完成 G0 和小场景回归、采样探针。
2. **技能/BC 数据和候选**：先收足事件覆盖；数据阶段可设置 2–4 小时墙钟上限，最多 4 个预定义 BC 候选。
   GPU 优化阶段以每候选约 1 GPU·小时为第一检查点，未通过 G1–G3 不自动加时。
3. **最终目标短 RL**：每个已达标候选先做约 20 万个新鲜物理帧/决策的有界试验，至少两个独立 seed。
   样本不足以得出胜负时补到预先规定的回合数量，而不是看训练曲线好看就宣布成功。
4. **正式扩展**：只有 G4 通过后，按 100–300 万帧一段扩大；每段有独立成绩和停止判断。
   不将某个算法通常需要千万帧当作本设计已经合理的证据。

立即停止：奖励/动作分布错误、非有限值、mask 导致全部合法射击消失、实际发射/命中长期为零、数据泄漏。
净击杀型若再次连续大量回合靠不射击回到零，回到技能/数据阶段，不加开枪次数奖励救曲线。
胜率型若真实胜率提高，可以保守；若关键技能退化且胜率也没有提高，则回滚检查点并排查。
退化和进步均用固定评估确认，不以重叠的最近 100 局窗口当作独立统计证据。

## 10. 正式验收与实时可见性

最终候选至少三组独立训练 seed，使用未参与选择的测试清单。
先按先导方差估计样本量；正式测试可从 2,000–5,000 个成对场景起步，按布局簇 CI 决定是否足以判定。

- rl_win：加权胜率超过 HY 至少 3 个百分点，且差值 95% CI 下界 >0。
- rl_frag：净击杀/局超过 GPT 至少 0.10，且差值 95% CI 下界 >0。
- 新模型同时进入实际部署阵容后另做回归，检查人数、地图、出生区域和特定对手组合中的退化。
- 导出后重放固定观测、动作概率、实际动作和完整回合；最终只发布经过验证的 actor。

所有数值在最终测试前冻结。如果改变目标/门槛，建立新版本，不事后降低标准通过。

TensorBoard 从第一条样本就记录：实际发射、命中、自毁、条件开火召回/精度、各动作熵、训练/固定评估、分人数成绩、样本覆盖与吞吐。
训练奖励、自然事件和最终主目标分开；评估暂停采样时明确显示阶段，不把曲线没更新误认为卡死。

## 11. 本方案的下一份可执行交付

先实现 V2 的事件账本、特征、动作分布测试、微任务与 G0–G3 验收脚本，再给出一次带资源上限的技能/BC 实验清单。
旧数据可做辅助/失败对照，V1 的坍缩权重不直接作为 V2 的主要起点。
在这些前置项可审查且通过前，不恢复旧任务、不启动大规模 PPO。
