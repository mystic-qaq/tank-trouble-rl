# V4：按能力验收推进的 policy 训练

这是一份重新实现的训练流程，不是旧 V3 的续跑入口。V3 保持停止，旧权重不兼容；原七份固定策略不修改。
默认命令只显示计划。此次交付进行实现测试和原始示范审计，不启动正式训练，不替换 Arena 模型。

## 游戏状态与网络选择

游戏的可见物理状态包含墙体、坦克位置/朝向/速度/冷却、所有存活子弹的位置/速度/寿命/反弹次数及自身子弹归属。
这些状态支持计算短期运动、拦截与反弹风险。V2 几何特征中的预测采用近似运动假设，不是真实未来，也不是命中或奖励的裁决者；裁决仍由原 JS 引擎完成。

对手内部策略记忆和随机流没有完全暴露，所以不能声称这个输入是严格完整的 Markov 状态。
但目前没有证据支持为此使用 GRU。V4 不使用循环网络、隐状态、上一动作、动作序列、历史角差或历史停滞计数。
输入层只选当前物理字段；改变被排除的历史字段，输出必须逐值不变。
“推测未来”由当前状态中的速度和物理几何、训练得到的动作偏好与价值函数承担，不把记住过去当作规划未来。

网络为 **3,582,086 参数**的前馈模型：地图 CNN、当前自身状态编码、坦克/子弹/瞄准候选的集合注意力、残差 MLP。
容量用于地图连通结构、多实体威胁和动作组合，不以占满显存为目标，也不继续任意扩大参数。
地图、实体特征均来自既有引擎观测；没有给模型提供教师的未来轨迹。

共同预训练输入教师风格编号，区分不同教师在同一状态下的不同合理动作，避免将互相矛盾的教师动作简单平均。
两条正式分支分别固定 HY/GPT 风格编号，再做对应教师的 DAgger。部署决策仍完全由神经网络产生。
技能示范也随机分配给 HY/GPT/reference 风格，避免技能只对 reference 编号有效。

动作是一个 **102 类联合分类**：3 种油门 × 17 档转向 × 2 种开火。
转向在 0 附近更密集，保留精细瞄准；最大量化误差为 0.125 个转向单位（当前规则下单帧约 0.006875 弧度）。
移动、转向、开火整体学习，不独立拼装三个教师动作，不额外每帧抛一次独立开火硬币。
机械开火可用性仅屏蔽冷却/弹药不允许的动作，没有加入代替模型战斗的战术安全控制器。

监督训练使用正常分类似然，不使用把概率推偏的正类权重。发射正例可优先采样，但用精确重要性权重校正回原目标分布。
随机策略固定使用温度 0.35；温度在训练前声明、写入权重并参与验收。不能在验收后偷偷换探索分布。
确定性与随机采样都逐帧运行真实 60Hz 引擎，不跳帧、不固定重复动作。回合时限为 60 秒。

## 阶段与硬性验收

`config.json` 是预先声明的工程验收要求，不是声称这些数值具有普适最优性。
任何条件未达到都停止、保留失败报告；脚本不会降低阈值、自动重试到过关，或以用完预算代替成功。
训练步数、时间和无进展轮数仅决定停止/检查频率。开发集筛选通过后，还必须通过一次独立晋级评估。

| 阶段 | 允许进入下一阶段所需证据 |
|---|---|
| G0：实现与数据 | 冻结策略校验；原引擎物理一致；动作标签与实际发射一致；模型/概率/回滚回归通过。完整读取原始数据并校验格式、有限值、标签、60Hz、整局划分、原生重放证据和文件 SHA-256。每个教师至少 20 条训练、5 条验证轨迹及 20 个训练发射正例，每类技能至少 100 条轨迹。 |
| G1：共同预训练 → DAgger | HY/GPT 两方向都通过：留出示范移动准确率 ≥85%（转向误差 ≤0.125），开火精确率 ≥70%、召回率 ≥60%，每方向至少 100 个验证发射正例；独立闭环实战中，学生减去 70% 教师主指标的配对 95% 区间下界 ≥0；并通过下述技能、安全、随机采样及分人数检查。 |
| G2：DAgger → PPO 试运行 | 每方向独立验收：上述保留示范指标仍合格；在**学生自己访问的未见过状态**上，两种执行模式的教师纠偏移动准确率 ≥85%、开火精确率 ≥70%、召回率 ≥60%，至少 100 个正例；实战主指标达到 90% 教师的配对区间要求；相对已验收 G1 权重不退化，并通过全部技能与安全检查。 |
| G3：PPO 小范围试运行 → 持续 RL | 至少 3 次真实、非零且通过整批 KL 检查的更新；旧概率重算最大误差 ≤0.001；平均精确 KL ≤0.01，逐状态 KL 的 P99 ≤0.05。另用独立实战套件确认仍满足 90% 教师要求、相对已验收 G2 不明显退化，技能与随机采样安全仍合格。此关证明允许继续学习，不代表 RL 已成功超越教师。 |
| G4：最终候选 | 在未用于选择模型的最终套件中，两种模式的主指标均严格超过 HY（胜率）/GPT（净击杀）：配对差值 95% 区间下界 **>0**。同时通过非退化、技能、安全检查。未通过时没有正式成功模型，也不发布。 |

所有闭环验收还同时要求：

- 每种模式每个模型 **2,240 局完整对战**：2–8 人各 32 个独立布局块，每块包含两种地图条件及全部席位。人数等权汇总，置信区间按布局块配对 bootstrap 4,000 次，不能将同一布局的席位当作独立样本。
- 一半地图条件使用实际 Arena 的两张图，另一半使用该阶段未见过的生成地图。开发、G1、G2、G3、最终测试的地图/布局随机命名空间分开；晋级报告不能作为继续调参的开发集。
- 确定性部署动作和 PPO 实际随机采样分布均验收。随机相对确定性的主指标区间下界不得低于 −0.02 胜率/−0.05 净击杀；自杀差值区间上界不得超过 +0.03 次/局。
- 学生相对教师的自杀差值区间上界 ≤+0.03 次/局；每个人数的主指标不能塌陷。净击杀教师基线非正时不用相对百分比偷换成更宽松目标；总教师基线必须胜率 ≥0.10 或净击杀 ≥+0.10/局。
- 发射 ≥100 次、击杀 ≥30 次；这些只是附加下限，不能代替实战成绩。
- 3 秒小范围内持续驱动且无发射的顶墙停滞比例 ≤max(15%, 教师+5个百分点)；无发射快速旋转比例 ≤10%。正常静止等待不直接算顶墙，也不加入“必须移动”的奖励。
- 每种执行模式 **384 个技能场景**（每类 64）：静态射击成功率 ≥80%、移动靶 ≥70%、反弹 ≥60%、炮口受阻安全 100%、单弹躲避/齐射躲避各 ≥90%；同时不得低于解析参考对应成功率的 90%。炮口受阻任务不允许任何 fizzle。
- 任何策略异常、缺局、错席位、没有完整回合结算或非有限值，都不能出具通过证书。

G2/G3/最终候选对前一已验收模型的主指标差值区间下界必须 ≥−0.02（胜率）/−0.05（净击杀/局）。
这些是有声明容差的非劣性要求，不应描述成“已证明逐轮严格提升”。

## 数据、DAgger 与 PPO

可复用 V3 原始 `.npy` 示范，**不能复用 V3 模型**。历史相关输入字段在新编码器中完全不读取。
复用前仍须完整 G0 数据审计，不因为“以前生成过”就跳过。原始胜者/正净击杀轨迹保留质量与教师风格，完整世界拥有唯一训练/验证划分。
缺少示范时可采集新数据；采集数量到达并不等于 G0 通过，覆盖和正确性验收仍单独进行。

DAgger 运行学生的确定性和随机版本，让 HY/GPT 在相同学生状态标注**完整教师动作组合**。
开火标签按教师自身移动后的炮口和冷却检查，不将教师开火配到学生另一套移动上。
新标签聚合进训练集，保留原多教师与技能数据；每轮用开发集选较好权重，不能固定选择最后一轮。
最终在晋级场景里另行统计学生状态上的纠偏准确率；这些晋级轨迹不回填训练。

PPO 使用完整代理回合、γ=1 的真实 Monte Carlo 回报：胜率为赢得回合 +1，净击杀为击杀他人减自毁。
死亡后仍结算尚存的己方子弹收益，死亡阶段没有 actor loss。无“前进、转圈、开火即奖励”等替代目标。
独立 critic 不共享 actor 参数；初始化为合法零基线，用后续真实回报学习，没有一个按固定 200 步自动放行的 critic 预训练阶段。

每批采样冻结 actor，更新前重新核对旧概率。更新尝试保存权重和 Adam 完整状态；更新后计算**整批全部状态、完整 102 类分布的精确 KL**。
越界则回滚权重及优化器，并减半学习率作有限次重试；仍失败就停止。回滚测试同时核对 Adam 动量，不只比较权重。
每批随机对局若超过 50% 自杀，记录整批结果并在 actor 更新前立即停止；这是额外的紧急止损线，不代替严格的阶段自杀率验收。
没有为了过关放大 KL 或概率重算阈值；禁用 TF32，不使用会使训练/评估路径不同的 dropout、BatchNorm 或 GRU。
不额外添加每帧探索熵奖励强迫随机开火；探索是否安全仍由闭环验收决定。

## 防止绕过验收

每份 `acceptance.json` 绑定以下证据：具体检查点文件 SHA-256、配置 SHA-256、引擎/固定策略/训练源码指纹、独立评估报告 SHA-256、原始及新增 DAgger 数据身份、前一阶段证书。
读取证书时重新计算通过条件，并递归检查交接链，不能只相信一个 `passed: true`。
G0 首次完整计算原始文件哈希；阶段交接还检查文件大小/修改时间，防止普通运行中的数据被改写。它不是针对恶意伪造时间戳的安全系统。

独立调用 `train.py` 的 DAgger/PPO 入口也必须提供匹配权重的前置证书，没有 `--skip-gates`。
改了源码或配置后旧证书失效，需要对应复核；未经验收的 `last-unaccepted.pt` 不能作为下一阶段初始化。
每个运行目录只允许新建，失败的运行不会自动覆盖或自动恢复。

## 命令与资源

本机查看计划不需要 PyTorch，不会申请 GPU：

```powershell
python -m policy.rl.v4.pipeline
```

在服务器上，只做契约与现有原始数据审计，**不训练**：

```bash
cd $RL_ROOT
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  .venv/bin/python -m policy.rl.v4.pipeline --prepare-only \
  --out runs/v4-prepare-NEW \
  --data runs/v3/data/multi runs/v3/data/skills --device cpu --seconds 1200
```

未来正式执行的完整入口（此次未执行）：

```bash
cd $RL_ROOT
CUDA_VISIBLE_DEVICES=GPU-86a509dc-7a70-80f7-881e-87e07eeaa783 \
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -u -m policy.rl.v4.pipeline --execute \
  --out runs/v4-production-NEW \
  --data runs/v3/data/multi runs/v3/data/skills --device cuda:0 --seconds 28800
```

不传 `--data` 时才采集新示范。传入已有数据但审计失败时直接停止，不自动采新数据耗资源。
监督预训练/DAgger 在可见卡范围内最多使用 4 卡，对同一个全局 batch 做 DataParallel 梯度聚合；全局 batch 仍为 512，不改变损失权重或验收标准。
四卡与单卡的加权损失、完整参数梯度有单独一致性检查。PPO 与实战评估仍按需单卡执行，32 个环境 worker；不强行占满空闲卡，不使用 6 卡或参数扫描。
共同 G1 通过后，两个目标可并行推进：四卡划成两个互不重叠的两卡组，每组独立完成对应 DAgger、PPO 试运行与正式 RL，单组阶段仍必须逐项验收。
两组最多共 64 个环境 worker；一个分支失败即停止该分支，不阻止另一条已通过自身前置验收的分支继续。没有至少两张显式可见卡时沿用顺序执行。
G0 同时建立发射帧索引，训练按轨迹成组随机读帧，避免每批对网络数据盘反复扫描整条轨迹；保留重要性校正与目标采样边际。
正式数据与输出存放在 `$RL_ROOT/runs`，`$RL_ROOT/runs` 仅为兼容软链接。迁移后重新生成 G0 证据，不沿用旧路径证书。
完整脚本的总预算到期就停止，不保证一份 8 小时预算能完成所有阶段；不会为赶进度减少独立验收或放行弱模型。

阶段入口帮助：

```bash
.venv/bin/python -m policy.rl.v4.train --help
```

目录中的 `pipeline.json`、阶段 `status.json`、`failure.json`、`acceptance-evidence.json` 与 `acceptance.json` 分别记录调度、训练、失败和验收。
TensorBoard 日志在各阶段 `tb` 目录：BC 损失、确定性/随机开发成绩、真实 PPO 回报、自杀、击杀、平均及 P99 KL。
观察损失和训练回报不能替代 `acceptance.json`。

## 实现依据与边界

DAgger 聚合学生自身访问状态上的教师标签，针对闭环分布偏移；参考 [Ross 等，2011](https://proceedings.mlr.press/v15/ross11a.html)。
PPO 使用当前策略采样、截断策略目标；参考 [Schulman 等，2017](https://arxiv.org/abs/1707.06347)。
这里的阶段阈值、联合离散动作、教师风格条件、严格回滚和晋级规则是本项目实现选择，不是论文替这些选择提供成功保证。

脚本通过测试只证明实现契约和失败保护得到检查，**不证明 V4 已经学会战斗**。
单次训练即使通过 G4，也不等于多种子可复现、长期在线学习安全或浏览器发布已完成；本脚本不自动部署、不自动发起新训练。
