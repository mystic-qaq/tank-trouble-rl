# minimax · Tank Trouble Arena 策略

一个"会算弹道"的坦克 AI。核心思路：**每一发子弹开出去之前，先把它整条弹道跑一遍模拟**，
确认这一枪能打中人、而且不会绕回来打自己，再扣扳机。

---

## 一、怎么接进 Arena

策略本体只有一个文件：`policy.js`，无依赖、不用构建、不读 DOM。

### 方式 A：ES Module（推荐）

```js
// 你的 arena 加载器里
import policy from './policy.js';                       // 默认导出 = 主函数
import { updateBot, createPolicy, decidePolicy } from './policy.js';
```

```js
// 或者按"工厂"方式用（每个坦克一份独立状态）
import { createPolicy } from './policy.js';
const brain = createPolicy();
...
const input = brain.update(tank, game, dt);   // -> { drive, steer, shoot }
```

### 方式 B：普通 `<script>` 标签

`policy.js` 里有 `export` 语句，用普通 script 标签加载会报语法错。
这种情况请用 **`policy.global.js`**（由 `policy.js` 自动生成，逻辑完全一致）：

```html
<script src="policy.global.js"></script>
<script>
  const input = window.TTPolicy.updateBot(tank, game, dt);
</script>
```

`window.TTPolicy` 上有：`updateBot` / `decide` / `createPolicy` / `configure` / `resetConfig` / `policy`。

### 主函数签名

```js
policy(tank, game, dt) -> { drive: -1|0|1, steer: -1|0|1, shoot: boolean }
```

和游戏内置 AI `TT.updateBot(tank, game, dt)` **完全同签名**，所以最省事的接法是直接顶替它：

```js
const orig = TT.updateBot;
TT.updateBot = (tank, game, dt) =>
  tank.index === MY_SLOT ? policy(tank, game, dt) : orig(tank, game, dt);
```

函数还做了**调用形态自适应**，下面几种传法都能用：

| 形态 | 写法 |
|---|---|
| A | `policy(tank, game, dt)` |
| B | `policy({ tank, tanks, bullets, map, dt })` |
| C | `policy({ self, game })` |

返回值里除了 `shoot` 还会附带一个别名 `fire`（兼容不同 Arena 的字段命名）。
**任何异常都会被吞掉并返回"不动、不开火"**，绝不会因为一个异常把整局带崩。

**接入前请确认一件事**：Arena 是否需要 `policy.js` 是 ESM 格式。
如果 Arena 用 `<script src>`（非 module）加载，把 `policy.global.js` 给它即可。

## 二、策略做了什么

| 能力 | 说明 |
|---|---|
| **弹道仿真** | 完整复刻 `js/entities.js` 里 `Bullet.update` 的几何：每弹一次衰减 0.7px、最多弹 5 次、炮口顶在墙里直接哑火、子弹与坦克用"线段 vs 圆"判定 |
| **弹道保真** | `test/verify-trace.mjs` 直接在真实对局里抓子弹的每一帧位置比对，**帧级最大偏差 0.0000px**（60 条随机弹道） |
| **整条弹道飞完** | 弹道仿真**不因为擦到别人就提前结束** —— 现实中对方会动，子弹会继续弹几面墙再绕回来 |
| **运动感知自伤判定** | 开火后我还会转向/进退/横移，子弹绕回来时撞的是"我移动后的位置"。自伤判定用**我自己的运动轨迹**，不是原地不动的圆 |
| **闪避基准正确** | 判定"要不要躲"时，比的是"最优躲避动作"和"原地不动"的净空差。只看最优净空的话，能躲到 50px 时策略反而会站着瞄准然后被打中 |
| **子弹闪避** | 把场上所有来弹（**包括自己反弹回来的弹**）按时间轴推演，枚举 17 种"转向 + 油门"组合，取净空最大的一种 |
| **预判射击** | 按目标当前速度做两轮迭代预判；**判定命中用"预测位置"而不是当前位置**——否则目标一移动就一枪不开 |
| **比例转向** | 满舵 3.3rad/s × 1/60 帧 = 0.055rad，比开火窗口还大 → 满舵会左右振荡永远对不准。改成"这一帧需要转多少就给多少舵量" |
| **反弹冷枪** | 直瞄不成时用镜像法算打墙折射角，只验证第一跳，成本极低 |
| **卡位进攻** | BFS 找出"对目标有直瞄 + 距离在安全带 + 不在别人射界里"的格子，再走格子路径过去 |
| **打后横移** | 开完一枪立刻侧移，不给对方补枪窗口（但**有子弹要打我时闪避优先**） |
| **锁定射手** | 子弹带 owner，谁朝我开火我就优先打谁 |
| **卡住自救** | 用**位移**而不是速度判断卡死（顶墙空转时速度仍有 40~50，位置却不动） |
| **僵局激进度** | 回合拖太久就缩短距离带主动压上，不让回合变成平局 |
| **安全撤离** | 场上多人同时朝我开火时，撤到没人看得见的格子 |

### 优先级（每帧按顺序决策）

```
闪避（有子弹要打我）  >  撤退（交叉火力）  >  瞄准开火  >  卡位推进  >  原地待命
```

## 三、可调参数

策略顶部有一个 `P` 对象，也可以运行时调用 `configure({...})` 覆盖
（**注意 `configure` 是合并语义**，只覆盖传进来的键；要回到出厂默认值请先调 `resetConfig()`）。

| 参数 | 默认 | 含义 |
|---|---|---|
| `aimTol` | 0.050 | 开火角度容差（弧度）。实际弹道仍会再验证一次，放宽不会打偏 |
| `standoffMin/Max` | 120 / 320 | 理想交火距离带（px） |
| `standoffIdeal` | 210 | 卡位时优先选择的距离 |
| `dodgeWant` | 40 | 净空小于该值必须全力躲开 |
| `dodgeSafe` | 34 | 净空小于该值连油门都要踩到底 |
| `dodgeHorizon` | 1.20 | 闪避推演时长（秒） |
| `dodgeGain` | 24 | 躲避比"原地不动"净空多出多少才值得换方向（px）。**0 = 关闭这条规则** |
| `dodgeWins` | 1 | 1 = 闪避压过"开火后横移"；0 = 横移覆盖闪避 |
| `maxLiveBullets` | 3 | 自己在场子弹上限 |
| `planInterval` | 0.12 | 射击方案刷新间隔（秒） |
| `planCandidates` | 4 | 每次最多仿真几个候选射击角 |
| `displaceTime` | 0.80 | 开火后横移时长（秒） |
| `aimMove` | 0 | 瞄准时是否移动：0=站定 1=被瞄准时移动 2=始终移动 |
| `crossRetreat` | 2 | 几发敌方子弹在飞就考虑撤退（0=关闭） |
| `leadFactor` | 0.94 | 预判提前量系数（1=完全按当前速度外推） |
| `rageAfter` | 25 | 回合超过多少秒开始加大压上力度（0=关闭） |
| `bankRange` / `bankWalls` | 420 / 10 | 冷枪：考虑多远的墙、每个目标最多试几面 |
| `traceHorizon` | 2.4 | 射击验证的弹道推演时长（秒） |
| `guardMode` | 1 | 自伤判定：0=只看当前位置，1=按"我移动后的位置" |
| `selfMargin` | 0 | 自伤判定的额外余量（px）。0 = 严格按真实命中半径 |
| `blockRule` | 2 | 敌人能不能替我挡枪：0=不信，1=按对方当前速度，2=要打在中心且早 0.15s |

## 四、实测成绩

用 `test/harness.mjs` 把游戏本体（`js/*.js`）装进 Node 的 vm 里跑**无头真实对局**，
地图、碰撞、子弹反弹全是游戏本体逻辑，不做任何简化。

### 对内置 AI（`js/ai.js`），8 辆坦克

> 席位会轮换（P1 的出生点系统性更好，见第七节第 9 条），每场先到 5 胜。

**三轮种子、240 个回合的汇总（`test/sweep8.mjs`，席位轮换）：**

| 指标 | minimax | 内置 AI 平均 |
|---|---|---|
| 回合胜率 | **95.0%**（228/240 回合） | 43.8% |
| 净击杀 | 540 | 约 94 |
| 自杀次数 | **25**（占死亡 4.7%） | **76.1** |
| 死亡次数 | 528 | 约 247 |
| 回合超时 | 6 / 758 回合 | 约 1 / 281 回合 |
| 策略异常 | **0** | — |

单场明细（`node test/bench.mjs 16 8 --seed=7000`，P1 固定）：

```
  minimax 胜场        : 71 / 80        内置 AI 平均胜场 : 35.0 / 80
  minimax 净击杀      : 201（自杀 9 次，死亡 210 次）
  基线平均自杀        : 76.1 次        minimax 策略异常 : 0
```

> 同一份代码在修复前（见下面"第五节：找出来的三个逻辑漏洞"）是 **83.8%**，
> 修复后 95.0% —— 提升主要来自闪避判据和自伤判定。
> 换成随机席位（`--shuffle`）复测三组种子：220/240 = **91.7%**，与轮换席位一致。
> 另一个全新种子（31415）：77/80 = **96.3%**。

### 不同人数（内置 AI 为对手）

| 坦克数 | 回合胜率 | 自杀 |
|---|---|---|
| 2 | 58/60 = **96.7%** | 1 |
| 4 | 56/60 = **93.3%** | 4 |
| 6 | 53/60 = **88.3%** | 3 |
| 8 | **95.0%**（240 回合） | 25 |

### 对不同风格的对手（`test/opponents.mjs`）

写了 4 种典型风格当对手：冲锋型、蹲坑型、狙击型、反弹冷枪型。
2 辆单挑时对四种风格分别是 61.8% / 67.8% / 72.7% / 87.0%。

8 辆混战时这几种对手会把回合拖成僵局（游戏本体没有回合时限，
双方都活着的回合会一直打下去，测试台只能用超时兜底），
所以绝对胜率参考意义有限；对照组实验（`test/versus.mjs`，
让**内置 AI 也坐同一个席位**打同样的对手）显示 minimax 全面占优：

| 对手 | minimax | 内置 AI |
|---|---|---|
| 狙击型（8 辆） | 6/40 = 15.0% | **0/34 = 0%** |
| 狙击型（2 辆） | 29/44 = 65.9% | **12/43 = 27.9%** |

### 性能

| 指标 | 数值 |
|---|---|
| 单次决策耗时 | **0.045 ms**（平均） |
| 最慢单次 | 6.8 ms |
| 帧预算占比 | **0.2%**（60fps 下 16.67ms/帧） |

> 内置 AI 每帧要遍历全部墙体做视线判断，策略把墙按格子分桶、自己写了一份
> 等价射线（`test/verify-raycast.mjs` 校验过 8 万条随机射线，**0 差异**），
> 所以本策略的 CPU 开销比内置 AI 还低。

## 五、找出来的三个逻辑漏洞（这版能赢的关键）

前一版策略已经有"弹道仿真 + 零自杀"，实测也能赢内置 AI。
但对着"蹲坑型 / 狙击型"对手时胜率崩到 1.5%，顺着这条线挖出了**三个逻辑漏洞**。
它们是这个策略真正值钱的部分，也是给别人写同类 AI 时最容易踩的坑。

### 怎么挖出来的

1. `test/opponents.mjs` 对 4 种对手风格：蹲坑型只有 1.5~11% 胜率，且 **90% 回合超时**。
2. `test/versus.mjs` 对照实验：让**内置 AI 也坐同一个席位**打同样的对手 ——
   对狙击型，内置 AI 0/34，minimax 6/40。说明不是对手变态，是策略有洞。
3. `test/selfkill.mjs`：统计自杀时子弹的飞行时长和弹跳次数 ——
   **90% 的自杀来自"弹跳 1~5 次后绕回来"的子弹**，不是正面命中。
4. `test/selfwhy.mjs` 判别实验（最关键的一步）：
   自杀时子弹路径有没有经过**我开火那一刻的位置**？
   → **44% 经过**（说明"当前位置判"本该拦住，是逻辑漏洞）；
   → **56% 没经过**（是我自己后来走进弹道的，必须算运动轨迹）。
5. `test/verify-trace.mjs`：推演弹道与游戏真实弹道**帧级偏差 0.0000px** ——
   证明仿真精度没问题，问题出在"谁会挡枪"和"我会不会动"两个判断上。

### 漏洞 1：弹道一碰到坦克就截断

真实情况对方会动。子弹擦过对方**当前位置**后，对方一动就漏过去了，
子弹继续飞、继续弹几面墙、绕回来打自己。
原来的实现一旦碰到坦克就停止仿真，于是"后面会不会打到我"根本没算。

**修法**：`traceBullet` 增加 `fullPath` 模式，撞到坦克也把整条弹道飞完，
并记录 `hits[]`（谁在第几秒被扫到、偏离中心多远、当时速度多少）。

### 漏洞 2：闪避推演把"自己"设成了忽略对象

原来的闪避推演传 `ignoreIndex = 自己`，等于"假装自己不在"——
自己的子弹绕回来打自己，**根本测不出来**。
更糟的是 `ownerIdx`（子弹主人）和"要保护谁"被混成了一个概念。

**修法**：拆成两个独立参数 —— `ownerIdx`（子弹主人，只用来决定出生保护）
和 `selfIndex`（要保护谁，用来判自伤）。

### 漏洞 3：闪避判据用错了基准线（影响最大的一条）

原来是"**最优躲避动作**的净空 < 40px 才躲"。
于是只要最优躲避能拿到 50px 净空，策略就认为"够安全"，
宁可站着瞄准也不躲 —— 然后被打中。

**修法**：拿"最优躲避"和"**原地不动**"的净空作比较，
差值超过 `dodgeGain` 才值得换方向（`best.gain`）。
另外"开火后横移"原来会**覆盖闪避**（横移优先），改成闪避优先。

### 附带修的两处

- **自伤判定从"静止的圆"改成"我自己的运动轨迹"**：
  新增 `projectPath / projectAfterShot`，按比例转向复刻移动物理，
  并模拟开火后的 90° 横移。开火后我还在转向移动，
  子弹绕回来撞的是"移动后的我"，用一个静止的圆判必然漏。
- **不再轻信"敌人会替我挡枪"**：擦边的一枪多半会漏（对方会动），
  所以只有"打在对方中心附近且早 0.15 秒以上"才认它能挡住。

### 效果

| | 修复前 | 修复后 |
|---|---|---|
| 回合胜率（240 回合 × 3 组种子） | 83.8% | **95.0%** |
| 自杀占死亡比例（对内置 AI） | 6.2% | **3.4%** |

## 七、几个已知的坑（写给以后维护的人）

1. **子弹会打回自己**。子弹只对主人有 0.07s 的出生保护，之后照样能把主人打死。
   而且**九成自杀是"子弹弹了几面墙绕回来"造成的**，不是正面命中。
2. **弹道仿真不能一碰到坦克就停**。真实情况对方会动：子弹擦过对方当前位置后，
   对方一动就漏过去了，子弹继续飞、继续弹、绕回来打你。
   所以必须把整条弹道飞完，再判断"谁先被打中"。
3. **闪避判据要用"原地不动"当基准线**。只判断"最优躲避动作的净空够不够大"是不够的：
   能躲到 50px 净空时策略会认为"够安全"，于是站着瞄准，然后被打中。
4. **自伤判定要用"我自己的运动轨迹"**，不是原地不动的圆 —— 开火后我还在转向和移动。
5. **炮口顶在墙里 = 这一发白打**。子弹出生点就在炮管前端（车心 + 28px），
   如果那里在墙里，子弹出生即哑火（`nx===0 && ny===0` 分支）。
6. **撞墙会掉速**。速度被墙挡一下会 ×0.55，所以贴着墙蹭不好转向。
7. **坦克不能横移**。车只能沿车头方向走，所以"侧移"必须先把车头转过去——
   这就是为什么"开火后横移"期间会暂时失去瞄准能力。
8. **命中判定是数组顺序先到先得**。同一发子弹同时擦到两辆坦克时，
   `game.tanks` 数组里靠前的先死（`js/game.js` 的子弹判定循环）。
9. **P1 出生点系统性更好**。`map.pickSpawns` 是贪心选点，第一个被挑中的格子不受
   "与其它出生点互不可见"的约束，所以 P1 平均能看到 13.1 个格子，P4 只有 8.9 个。
   镜像对局里 P1 拿 48 胜、P8 只有 5 胜。**这是游戏本身的性质，所有策略都吃这个红利/亏**，
   所以测胜率一定要轮换席位，否则结论全是假的。
10. **游戏本体没有回合时限**：回合只在剩 ≤1 辆坦克时结束。
    如果所有对手都躲在角落不动，回合会永远打不下去 —— 测的时候记得留超时兜底。
