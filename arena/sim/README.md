# 模拟协议：跑多少局、怎么排、怎么跑得快

> 当前正式游戏、Arena 和训练已统一为 60 秒。下文的性能与胜率数值来自旧 90 秒实验；新统计请使用新的 `--out` 目录。调度器会拒绝跨规则混合续跑。

> 目标：回答「不同策略在不同出生点 / 不同人数 / 不同名单下的胜率与击杀」。
> 结论先说：**分三阶段跑，合计约 7,600 局，这台机器 1.5 小时出可发布的表**；
> 想要 ±1pp 的精度再翻 4 倍。

---

## 一、先想清楚「局数买的是什么」

结果里的波动有三种来源，只有第一种能靠「多跑几局」压下去：

| 误差来源 | 表现 | 怎么压 |
| --- | --- | --- |
| **抽样误差** | 策略自己有随机决策，同一局重跑结果不同 | 局数 ↑，按 `1/√n` 收敛 |
| **布局误差** | 出生点/地图不同，强弱排序会变 | 只能增加**不同布局的数量**；同一布局重复 100 遍没用 |
| **设定误差** | 只测了某个名单，换个名单结论就变 | 覆盖设计，或用 Plackett–Luce 外推 + 留出验证 |

第三条最容易被忽略：8 个策略有 `C(8,2)+…+C(8,8) = 247` 种名单，全枚举 × 2 张图 × 每个 N 至少 200 局 ≈ 70 万局，不现实。
所以正确做法是**跑一个配平的子集，再用模型外推**，而不是把某个名单刷到 ±0.5pp。

## 二、样本量：看你要分辨多大的差距

`node arena/sim/power.mjs` 会打印下面这些表（DEFF=1.15 是可调的设计效应，见第三节末）。

### 2.1 8 人混战，单个策略胜率的 95% CI 半宽

| 真实胜率 | ±3pp | ±2pp | ±1.5pp | ±1pp |
| --- | --- | --- | --- | --- |
| 12.5%（均分基线） | 537 | 1,208 | 2,148 | 4,832 |
| 20% | 786 | 1,768 | 3,142 | 7,069 |
| 30% | 1,031 | 2,320 | 4,124 | 9,278 |

### 2.2 判定「A 真的比 B 强」，需要多少局（80% power）

| 对比 | Δ=8pp | Δ=5pp | Δ=3pp | Δ=2pp |
| --- | --- | --- | --- | --- |
| 30% vs 20% | 692 | 1,770 | 4,915 | 11,058 |
| 25% vs 25% | 706 | 1,806 | 5,015 | 11,283 |
| 12% vs 8% | 280 | 717 | 1,990 | 4,478 |

注意方差项是 `p₁(1-p₁)+p₂(1-p₂)+2p₁p₂`：一局只有一个赢家，两个策略的胜率**负相关**，
所以「同场比较」比「两批独立实验比较」省一半以上的局。

### 2.3 1v1 单挑：p≈0.5 时最费局

| 每对局数 | 单对胜率 95%CI | 可分辨差距（80% power） |
| --- | --- | --- |
| 50 | ±14.9pp | ±42.5pp |
| 100 | ±10.5pp | ±30.0pp |
| 200 | ±7.4pp | ±21.2pp |
| 400 | ±5.3pp | ±15.0pp |
| 800 | ±3.7pp | ±10.6pp |

**所以不要试图把每一对都刷准**。28 对 × 200 局只能分辨 21pp，几乎没用。
正确做法：每对 80 局，然后把 2,240 局**池化**进 Plackett–Luce / Bradley–Terry，
用全部对局一起估 8 个强度参数 —— 强度差的 CI 会缩到 ±2~3pp，比单对硬刷省 10 倍。

### 2.4 反查：给定局数，主榜能到多准

| 局数 | CI 半宽（p≈0.25） |
| --- | --- |
| 400 | ±4.6pp |
| 800 | ±3.2pp |
| 1,600 | ±2.3pp |
| 2,400 | ±1.9pp |
| 6,000 | ±1.2pp |

## 三、实验设计（`sim/plan.mjs` 里就是这么生成的）

### 3.1 三层结构

| 阶段 | 内容 | 回答什么问题 |
| --- | --- | --- |
| `main8` | 8 人全阵容，2,400 局 | 谁强（主榜） |
| `count` | N=3…7，每档 8–30 个配平名单 | 人多对谁有利 |
| `duel` | 28 对单挑，每对 80 局 | 两两谁克谁 |

8 人阶段不做名单抽样 —— 8 个全上，省掉一整个维度。

### 3.2 配平：让「席位」和「策略」正交

每个 block = N 局：

- **同一套出生坐标**（同一个 `spawnSeed` 与地图）；
- **策略逐局轮转**：第 r 局第 s 个席位放 `players[(s + r) % N]`。

于是每个 block 内，每个策略恰好坐遍 N 个席位，席位与策略完全正交；
下一个 block 换一套出生布局，地图 A/B 交替。局数取 **2N 的倍数**时两张图也配平。

### 3.3 配对：名单之间共用布局（common random numbers）

`count` 阶段同一个 N 的所有名单共用同一个 `baseSeed`，因此**逐局看到完全相同的出生坐标**；
`duel` 阶段 28 对共用同一个 `baseSeed`。这样名单之间的差异不是「运气不同」，而是同条件对决，
配对比较的方差比独立比较小一个量级。

> 出生点用的是独立的 `game.spawnRandom`，与策略消耗的 `Math.random` 流完全隔离，
> 所以「布局相同」这件事不会因为策略不同而被破坏。

### 3.4 名单抽样：边际配平

`balancedRosters(n, count)` 每次挑「出场次数最少」的 n 个，再去重 + 局部修补到
**每个策略出场次数差 ≤ 1**（8 策略 80 个名单时是 47~49 次）。
这样边际胜率不会被「谁总跟强手同场」污染。

### 3.5 设计效应（DEFF）

同一套布局下的 N 局不是独立样本。`analyze` 会把 bootstrap 方差除以二项方差，
直接报出实测 DEFF：

- 预算里默认按 **1.15** 算（即「名义 2,400 局 ≈ 有效 2,100 局」），偏保守；
- **实测 pilot（320 局 8 人、40 个布局簇）DEFF ≈ 0.96~0.99** ——
  因为每局都换布局、席位还轮转，簇内相关几乎为 0，1.15 的假设是安全的；
- 但如果把「同一布局重复很多遍」当成样本量（很多跑法都这么干），DEFF 会显著 > 1，
  名义局数就是虚的。`analyze` 每次都会打印这个值，用来体检设计。

## 四、怎么跑

```bash
# 自检（约 2 分钟）：验证流水线通不通
node --experimental-vm-modules arena/sim/run.mjs --budget smoke --fresh

# 摸底（约 15 分钟）：±5~8pp，够看趋势
node --experimental-vm-modules arena/sim/run.mjs --budget pilot

# 粗排（约 35 分钟）：±3~4pp
node --experimental-vm-modules arena/sim/run.mjs --budget quick

# 可发布（约 1.5 小时）：主榜 ±2pp
node --experimental-vm-modules arena/sim/run.mjs --budget standard --jobs 20

# 出表
node arena/sim/analyze.mjs
node arena/sim/analyze.mjs --predict gpt,hy,qwen      # 预测没跑过的名单

# 只要某一层
node --experimental-vm-modules arena/sim/run.mjs --budget standard --stages main8
```

### 预算档

| 档 | 局数 | 主榜 CI | 实测耗时 |
| --- | --- | --- | --- |
| smoke | 194 | — | ~2 min |
| pilot | 1,144 | ±5~8pp | ~15 min |
| quick | 3,552 | ±3.2pp | ~45 min |
| standard | 7,612 | ±1.9pp | ~1.6 h |
| deep | 19,116 | ±1.2pp | ~4 h |

时间按「聚合吞吐 ≈ 5.5 个单核」估算，见第六节。

### 断点续跑

- 每局结束立刻 append 到 `output/sim/rounds.jsonl`，Ctrl-C / 崩溃不丢已完成的对局；
- 重跑同一条命令会按 `jobId#roundIndex` 跳过已有记录；
- `--fresh` 才会清空。
- 任务按「轮次」交错派发，中途停下时每个配置都有近似等量样本，可以先出一版临时表。

## 五、输出怎么读

`analyze.mjs` 打四块：

1. **按人数分表**：胜率 + 聚类 bootstrap CI、击杀/局、**击杀/分钟**、自杀/局、阵亡率、平均存活。
   - 击杀/局 会被存活时长污染（活得久自然杀得多），跨打法比较要看击杀/分钟；
2. **PL 潜在强度**：1.00 = 全场平均，可直接比较不同名单；
3. **单挑矩阵**（`duel`）：行方对列方的胜率；
4. **出生点分桶**：同一人数内，按「开口数」「离中心距离」「象限」分桶的胜率。
   pilot 结果：**开口数 3 vs 4 几乎没有差异**（11.1% vs 11.3%），
   真正分得开的是**离中心距离** —— 8 人局里近中心 5.6%、极远 14.0%（n≈300 vs 1,200）。
   也就是说「出生点重不重要」的答案是：**看位置，不看开阔度**。

### 口径必须统一

- **胜率分母**：`wins / 全部局`（平局算没赢）。90 秒超时记为平局，实测占 10%~12%，
  报告里要单列；想看「有效局胜率」就用 `wins / (rounds - draws)`。
- **自杀**：自己的子弹打死自己。`净击杀 = 击杀 - 自杀`，比裸击杀更能区分水平。
- **不要跨人数比胜率**：8 人局基线 12.5%，2 人局 50%，比绝对值没有意义，要比「相对基线的倍数」。
- **不要用「两个 CI 是否重叠」判断差异**：8 个策略 28 次比较，误判率会膨胀到 ~30%。
  要判定 A>B，直接用配对 bootstrap 差值 CI（`analyze` 的 byN 数据里存了逐局结果，可扩展）。

## 六、为什么快不起来，以及怎么最快

### 6.1 时间花在哪（实测拆解）

8 人局 1,034 帧的一次采样：

| 项目 | 占比 |
| --- | --- |
| GLM / GPT / HY / Kimi 的 `update()` | **90.4%** |
| DeepSeek / minimax / Qwen | 7.3% |
| 引擎物理 + 碰撞 + 特效 | **1.3%** |

也就是说：**瓶颈全在策略的 BFS / 射线检测**，优化引擎物理毫无意义。
建沙箱 + 编译 8 份策略只要 **9.6ms/局**（占单局 6.8s 的 0.15%），
所以「复用沙箱」这类优化不用做，做了也看不出来。

### 6.2 并行能到多少（i9-13980HX，32 逻辑核）

| 并发 | 8 人局吞吐 | 相对单核 |
| --- | --- | --- |
| 1 | 8.8 局/分 | 1.0× |
| 4 | 24.6 局/分 | 2.8× |
| 8 | 30.3 局/分 | 3.4× |
| 12 | 40.0 局/分 | 4.5× |
| 16 | 43.6 局/分 | 4.9× |
| 24 | 57.6 局/分 | 6.5× |

纯计算基准能线性扩到 25 核，所以**不是核数不够，也不是 CPU 配额**；
是这批策略的访存模式把缓存/内存带宽打满（外加长时间满载后的降频）。
结论：**开 16~20 个 worker 就够，再加只是让每个 worker 变慢**。

### 6.3 提速手段排序

| 手段 | 收益 | 代价 |
| --- | --- | --- |
| 两阶段跑（先 300 局估方差，再定总预算） | 省 20~30% | 无 |
| 换 A 的名单做「留出验证」，不要全枚举 | 省一个数量级 | 需要模型 |
| 用 PL 池化代替「每对刷准」 | 省 5~10 倍 | 依赖 IIA 假设 |
| 并发 16~20 | 5~6× | 无 |
| 降低 90s 超时上限到 60s | 省 ~20% 模拟时间 | 会多出平局，口径要重算 |
| 复用沙箱 / 缓存地图 | < 1% | 不值得做 |

### 6.4 一个容易忽略的浪费

8 人局平均 31.7s 模拟时长，但 **22/192 局打满 90s 超时**，这些局吃掉了
**约 1/3 的模拟时间**却只产出「平局」一个信息。
如果只是给开发期看趋势，可以把 `MAX_FRAMES` 降到 60s（`arena.mjs` 顶部），
省 15~20% 时间；对外发布的数字不要这么跑。

## 七、这套流程里已经踩过的坑

1. **口径不一致**：各家 README 的「胜率」分母不同（有的按 `场数×5×种子数`，有的按实际回合）。
   `arena/validate.mjs` 存在的意义就是统一重测。
2. **座位红利**：不轮转的话 P1 会白吃 2~4 个点。轮转后每个策略的座位红利恰好 0.0pp。
3. **策略状态串味**：每局必须新沙箱。策略里的 `WeakMap` 缓存会跨局残留。
4. **出生点没有记录**：旧战报只存 `spawnSeed`，无法回答「哪个位置好」。
   现在 `playRound` 会把每个席位的 `x/y/朝向/开口数` 一起返回。
5. **平局不算负**：把超时当失败会系统性低估防守型策略。
